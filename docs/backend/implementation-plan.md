# OCEC Portal Backend Implementation Plan

วันที่: 11 ตุลาคม 2026
สถานะ: งานลำดับ 1–9 ทำในโค้ดและ migration ในเครื่องแล้ว; ก่อนเปิดใช้งานจริงยังต้องเชื่อม Google Workspace, ตรวจรับในฐานข้อมูล/บัญชีจริง และ deploy
ขอบเขต: OCEC Portal เท่านั้น แยกจาก OCEC-Cert

## เป้าหมาย

ทำระบบสมัครสอบและจัดการหลังบ้านที่ใช้ข้อมูลจริงผ่าน API, PostgreSQL และบริการ Google Workspace โดยเก็บ OCEC Portal แยกจาก OCEC-Cert

## สถาปัตยกรรมที่เสนอ

- ใช้ Fastify API service ของ Portal ใน Railway project เดิม
- ใช้ PostgreSQL service ของ Portal แยกจากฐานข้อมูล OCEC-Cert
- รัน worker loop ของคิว PostgreSQL ภายใน Portal API service เพื่อไม่เพิ่ม Railway service; แยก worker เป็น service ภายหลังได้เมื่อมีโควตาและปริมาณงานรองรับ
- ไม่ใช้ worker หรือฐานข้อมูลร่วมกับ OCEC-Cert
- ใช้ PostgreSQL เป็นแหล่งข้อมูลจริง ระบบภายนอกเป็นปลายทางสำหรับซิงก์หรือเก็บไฟล์
- ใช้คิวงานที่บันทึกใน PostgreSQL ในระยะแรก เพื่อไม่เพิ่ม Redis ก่อนจำเป็น
- ให้ React อ่านและเขียนข้อมูลใช้งานจริงผ่าน API เมื่อ `VITE_BACKEND_ENABLED=true`

## กติกาธุรกิจที่ถือว่ายืนยันแล้ว

### ผู้ใช้และใบสมัคร

- เข้าระบบด้วย Google; ผู้ประสานงานโรงเรียนหนึ่งบัญชีส่งใบสมัครได้หลายคน ทั้งกรอกฟอร์มและนำเข้า Excel
- ป้องกันใบสมัครซ้ำด้วยชื่อภาษาอังกฤษ วันเกิด โรงเรียน รายการสอบ และรอบเดียวกัน แล้วพาไปดูใบสมัครเดิม
- ผู้สมัครแก้ข้อมูลที่อนุญาตได้ถึงวันปิดแก้ไข; รายการสอบ ระดับชั้น รูปแบบสอบ และศูนย์สอบถูกล็อกตามกติกา
- บัญชีเดียวอาจทำหน้าที่ผู้สมัครและผู้ประสานงานโรงเรียนได้; ความเป็นเจ้าของใบสมัครและความสัมพันธ์กับโรงเรียนต้องเก็บแยกจากตัวตน Google
- แอดมินทุกคนที่ได้รับอนุญาตมีสิทธิ์ทำงานหลังบ้านเหมือนกัน และระบบต้องบันทึกประวัติการเปลี่ยนแปลงสำคัญ

### รอบสอบและข้อมูลตั้งต้น

- ใช้แค็ตตาล็อกระดับชั้นและศูนย์สอบส่วนกลาง แล้วเลือกค่าที่ใช้ได้แยกในแต่ละการ์ดรายการสอบ
- ใบสมัครเก็บ snapshot ของชื่อ/รหัส/ราคา ณ เวลาสมัคร เพื่อไม่ให้การแก้ catalog เปลี่ยนประวัติเดิม
- Online Exam ใช้ `Online : Home Base` รหัส `500`; รอบ Paper-Based เลือกได้จากศูนย์ที่เปิดในรอบนั้น
- กำหนดการ วันเปิด/ปิดรับสมัคร และวันปิดแก้ไขผูกกับรอบสอบ

### การชำระเงินและสลิป

- ไม่มี payment gateway; ชำระด้วยการโอนและให้แอดมินตรวจ
- ใบสมัครรายบุคคลและ Final แนบสลิปแยกใบ; ใบสมัครโรงเรียนรวมยอดผู้เข้าสอบและข้อสอบเก่าทั้งชุดเป็นบิลเดียว แต่แอดมินอนุมัติใบสมัครแยกคน
- เมื่อสลิปชุดโรงเรียนมีปัญหา แจ้งผู้ประสานงานเท่านั้น; ลิงก์แก้สลิปแทนสลิปทั้งชุด ใบที่ยังรอตรวจกลับเข้าคิว ส่วนใบที่อนุมัติแล้วคงสถานะเดิม
- ตั้งค่าบัญชีรับเงินส่วนกลางใช้ได้กับทุกรอบ และบันทึกบัญชีที่เลือกกับธุรกรรม
- บัญชีประธานและบัญชีอื่นมีประเภทกำกับ; การบันทึกบัญชีภายนอกสำหรับบัญชีอื่นเป็นงาน manual ไม่มีการเชื่อมระบบบัญชี
- แอดมินตรวจภาพสลิปแล้วอนุมัติได้ โดยระบบบันทึกผู้อนุมัติและเวลาอนุมัติ แต่ไม่เก็บบัญชีปลายทาง ยอดยืนยัน หรือเวลาโอน
- ลิงก์แก้สลิปใช้ได้ครั้งเดียวและยังใช้ได้หลังปิดรับสมัครจนกว่าจะมีการอัปโหลดสลิปใหม่
- หากเปลี่ยนรูปแบบสอบจาก Online เป็น Paper-Based ให้แอดมินบันทึกส่วนต่าง 100 บาทและแนบสลิปเพิ่ม; เปลี่ยนจาก Paper-Based เป็น Online ไม่มีการคืนส่วนต่าง

### Google Drive และรูปเกียรติบัตร

- เก็บสลิปใน Google Drive แยกจากรูปเกียรติบัตร และจัดโฟลเดอร์ให้ค้นได้จากรายการสอบกับรอบ
- เก็บ file ID/ข้อมูลอ้างอิงใน Portal; หากไฟล์ถูกลบจาก Drive ข้อมูลใบสมัครและการชำระเงินยังอยู่ แต่หน้าเว็บเปิดดูไฟล์นั้นไม่ได้
- รูปเกียรติบัตรเป็นตัวเลือก อัปโหลดได้หลังอนุมัติจนถึงวันปิดแก้ไข และผู้สมัครหรือผู้ประสานงานโรงเรียนเป็นผู้อัปโหลดได้
- แยกโฟลเดอร์รูปตามรายการสอบ/รอบ ตั้งชื่อ `เลขประจำตัว_ชื่อ_นามสกุล` โดยใช้ชื่อภาษาอังกฤษ และอัปโหลดใหม่แทนไฟล์ปัจจุบันของผู้สมัคร
- เก็บประวัติใบสมัครและการชำระเงินในฐานข้อมูลโดยไม่ลบอัตโนมัติ

### อีเมลและ Google Sheets

- เริ่มแจ้งเตือนทางอีเมล: สรุปใบสมัคร/อนุมัติ/ผลสอบส่งไปอีเมลติดต่อในใบสมัคร; ปัญหาสลิปชุดโรงเรียนส่งถึงผู้ประสานงานเท่านั้น
- ส่งเฉพาะใบสมัครที่แอดมินอนุมัติแล้วเข้า Google Sheets
- แยก tab ตามรายการสอบและรอบสอบ; ผู้สมัครที่เลือก 3 รายการจะมี 3 แถวใน tab ที่ตรงกัน หนึ่งแถวต่อ Application Item ID และการแก้ไขเขียนทับแถวเดิมโดยใช้ Application Item ID; ซิงก์ทางเดียวและ retry อัตโนมัติ

### ผลสอบ Final และเลขประจำตัว

- นำเข้าผลสอบเป็นฉบับร่าง ตรวจการจับคู่และรายการขัดแย้งก่อนประกาศ
- ผู้ได้ Gold/Silver/Bronze มีสิทธิ์ Final; สำหรับ BBB ให้รางวัล 1st/2nd/3rd เทียบตามเกณฑ์เหรียญเดียวกัน ข้อนี้ให้ถือเหนือข้อความเก่าที่ขัดกันในเอกสารข้อกำหนด
- ประกาศผล Heat แล้วเปิดรอบ Final ให้ผู้มีสิทธิ์โดยอัตโนมัติ โดยแอดมินกำหนดเวลาปิดหรือปิดเองได้
- สร้างเลข Heat หลังปิดรับสมัครและให้แอดมินยืนยันก่อนสร้าง สำหรับทุกใบสมัครที่ส่งแล้วไม่ว่าสถานะอนุมัติหรือไม่; ใช้รหัสศูนย์ 3 หลักตามด้วยลำดับ 4 หลัก เริ่ม 0001 แยกตามศูนย์ และเรียงศูนย์/ลำดับระดับชั้น/ชื่ออังกฤษ A–Z
- เลข Final นำเข้าจากไฟล์ จับคู่ด้วยชื่อภาษาอังกฤษและโรงเรียน และพักรายการที่ไม่พบหรือจับคู่ได้หลายใบสมัครให้แอดมินตรวจ
- หน้าประกาศผลเป็นข้อมูลสาธารณะ ค้นหาชื่อหรือเลขประจำตัวและกรองตามรายการสอบ รอบ และระดับชั้น; เมื่อประกาศแล้วล็อกผลสอบ

## โมเดลข้อมูลหลัก

- `users`: Google subject, email, ชื่อ และสถานะ; ความสัมพันธ์ผู้สมัคร/ผู้ประสานงานเก็บแยกจากตัวตน และแอดมินที่อนุญาตใช้สิทธิ์เต็มเหมือนกัน
- `applicants`: ข้อมูลผู้เข้าสอบ รวมชื่อภาษาอังกฤษแบบแยก first/middle/last, โรงเรียน, วันเกิด และช่องทางติดต่อ
- `competitions`, `exam_rounds`, `grade_catalog`, `exam_centers`, `past_papers`: catalog และการตั้งค่ารอบ
- `applications`, `application_items`: ใบสมัครต่อผู้เข้าสอบ, รายการสอบ/ระดับชั้น/รูปแบบ/ศูนย์สอบ และ snapshot ราคา
- `school_batches`, `payments`, `payment_slips`: ชุดสมัครโรงเรียน ยอดรวม สลิป และสถานะตรวจ/อนุมัติ
- `payment_accounts`: บัญชีรับเงินกลางและประเภทบัญชี
- `exam_ids`, `results`, `final_invitations`: เลขสอบ ผล และสิทธิ์ Final
- `certificate_photos`: Drive file ID, ชื่อไฟล์, รายการสอบ/รอบ และเวลาที่อัปโหลด
- `audit_logs`, `integration_jobs`: ประวัติการเปลี่ยนแปลงและคิวซิงก์/ส่งอีเมล

ข้อมูลทางการเงินและใบสมัครควรเก็บ snapshot และบันทึก audit แทนการอาศัยค่า catalog ปัจจุบัน

## ลำดับส่งมอบ

### ระยะ 0 — เตรียมข้อกำหนดและสัญญา API

- ปรับ `OCEC-Portal-Requirements.md` ให้สะท้อนคำตอบล่าสุดและเอาหมายเหตุที่คลี่คลายแล้วออก
- กำหนด request/response ของหน้าที่มีอยู่ โดยไม่เปลี่ยน UI flow
- ระบุค่าที่เป็น configuration เช่น Google OAuth, Google Workspace OAuth, Drive folders, Google Sheet ID และ Railway environment variables

### ระยะ 1 — พื้นฐาน API และข้อมูล

- วางโครง Node.js API และ PostgreSQL migrations
- ทำ Google Login, session/cookie ที่ปลอดภัย และกำหนดการ provision แอดมิน
- ทำ catalog API และ seed ข้อมูลตั้งต้นที่ยืนยันสำหรับ staging
- เชื่อมหน้าหลังบ้านและหน้าผู้สมัครกับ API โดยเริ่มจากข้อมูล catalog

### ระยะ 2 — ใบสมัครและการสมัครโรงเรียน

- ทำสร้าง/อ่าน/แก้ไขใบสมัครและกติกาสิทธิ์แก้ไข
- ทำการตรวจใบสมัครซ้ำและการเก็บ snapshot ราคา/ตัวเลือก
- ทำ Excel upload preview, ตรวจซ้ำ/ตรวจค่ากับ catalog ฝั่ง server และสร้างชุดโรงเรียนแบบ transaction
- ทำการคำนวณยอดรายคนและยอดรวมชุดโรงเรียน

## สถานะการพัฒนาล่าสุด

- ใบสมัครรายคนและชุดโรงเรียนบันทึก PostgreSQL; ชุดโรงเรียนคิดเงินและอัปโหลดสลิปหนึ่งบิล อนุมัติรายคนได้
- API ตรวจรอบสอบที่เปิด วันรับสมัคร ระดับชั้น ศูนย์สอบ รูปแบบสอบ อีเมลเข้าสอบ ข้อสอบเก่า ราคา และรายการซ้ำที่ฝั่งเซิร์ฟเวอร์ก่อนบันทึก
- หลังล็อกอิน แอดมินโหลดคิวทั้งหมดจากฐานข้อมูล; ผู้สมัคร/ผู้ประสานงานโหลดเฉพาะใบสมัครของบัญชีตัวเอง
- หน้าตรวจบันทึกบัญชีรับโอน ยอดโอน และวันเวลาโอนที่แอดมินยืนยันเองก่อนอนุมัติ; ตรวจยอดให้ตรงกับยอดที่ระบบคำนวณ แล้วเก็บผู้อนุมัติ เวลาอนุมัติ และ audit log
- ส่งอีเมลผ่าน Gmail API ด้วยคิว PostgreSQL; ขอเปลี่ยนสลิปสร้างลิงก์ใช้ครั้งเดียวหมดอายุเมื่อไม่ได้ใช้ภายใน 3 วัน และชุดโรงเรียนแจ้งผู้ประสานงาน
- สลิปและรูปเกียรติบัตรเก็บ Google Drive แบบ private; ผู้สมัครที่ผ่าน Google verification หรือผู้ประสานงานอัปโหลดรูปได้หลังอนุมัติจนถึงวันปิดแก้ไข
- Google Sheets รับข้อมูลที่อนุมัติแล้ว หนึ่งแถวต่อรายการสมัคร พร้อม retry queue และแอดมินตรวจสถานะ/ลองใหม่ได้
- ผลสอบและเลข Final มี draft, conflict review และ publish; เลข Heat สร้างหลังปิดรับสมัคร ส่วนผล Heat ที่ผ่านเกณฑ์เปิด Final อัตโนมัติ
- รายงานรายชื่อและข้อสอบเก่าส่งออก Excel ได้จากข้อมูลใบสมัครที่โหลดจาก API; ตัวอ่าน/เขียน Excel ใช้แพ็กเกจที่รองรับ `.xlsx` และ `.csv`
- route หลักใช้ path ปกติ เช่น `/apply`, `/applications`, `/results`, `/portal-admin/results`; server ส่ง SPA entry point เมื่อเปิด URL ย่อยโดยตรง

### ลำดับงานที่แนะนำก่อนเปิดใช้งานจริง

ทำตามลำดับนี้เพราะแต่ละช่วงต่อยอดจากข้อมูลและสิทธิ์ที่ช่วงก่อนหน้าวางไว้ รายละเอียดตรวจรับของแต่ละข้อใช้เป็นเกณฑ์ปิดงานได้

1. **เสร็จ — ทำ catalog หลังบ้านให้บันทึกฐานข้อมูลจริง** — เพิ่ม/แก้/ปิดรายการสอบ รอบสอบ ระดับชั้น ศูนย์สอบ ข้อสอบเก่า และบัญชีรับเงินผ่านหน้าแอดมิน พร้อม validation, transaction และ audit log; รายการที่ถูกอ้างอิงจะถูกปิดแทนการลบถาวร
2. **เสร็จ — ทำการดูและแก้ใบสมัครหลังส่ง** — ผู้สมัครแก้ใบของตัวเอง และผู้ประสานงานแก้ผู้สมัครในชุดของโรงเรียนได้จนถึงวันปิดแก้ไข; backend ตรวจเจ้าของ/สถานะ/กำหนดเวลา ล็อกข้อมูลสอบและราคา และเก็บประวัติก่อน–หลัง
3. **โค้ดเสร็จ; รอเชื่อม Drive OAuth — ย้ายไฟล์สลิปไป Google Drive** — สลิปใหม่เก็บในโฟลเดอร์แยกรายการ/รอบ บันทึก Drive file ID และเปิดดูผ่าน API ส่วนตัว; สลิปเดิมที่เก็บเป็น `bytea` ยังเปิดได้ระหว่างย้ายข้อมูล หากไฟล์ถูกลบจาก Drive ข้อมูลใบสมัครและการเงินยังอยู่
4. **เสร็จ — Gmail API และคิวส่ง** — อีเมลรับใบสมัคร/อนุมัติ/แจ้งแก้สลิปเข้า PostgreSQL outbox ใน transaction เดียวกับการเปลี่ยนข้อมูล; Gmail API ส่งผ่าน HTTPS และ retry ได้จาก worker ที่อยู่ใน Portal API เดียวกัน
5. **เสร็จ — แจ้งปัญหาและเปลี่ยนสลิป** — ลิงก์สุ่มใช้ครั้งเดียว หมดอายุเมื่อไม่ได้ใช้ภายใน 3 วัน; สลิปโรงเรียนแทนทั้งบิล แจ้งผู้ประสานงานเท่านั้น ใบที่ยังรอตรวจกลับเข้าคิว ส่วนที่อนุมัติแล้วคงเดิม พร้อม audit log
6. **เสร็จ — Google Sheets sync หลังอนุมัติ** — สร้าง workbook แยกปีและ tab แยกการแข่งขัน/รอบ หนึ่งแถวต่อ Application Item ID; upsert โดยค้นหา ID เพื่อเขียนทับแถวเดิม งาน retry อยู่ใน PostgreSQL และแอดมินดูสถานะ/ลองใหม่ได้
7. **เสร็จในโค้ด — ผลสอบ เลขประจำตัว และสิทธิ์ Final** — เลข Heat สร้างได้หลังปิดรับสมัครสำหรับทุกใบสมัครที่ส่งแล้วแม้ยังรอตรวจ; Excel ผลสอบบันทึก draft และพักแถวที่ไม่พบ/ซ้ำ/ข้อมูลไม่ตรงให้ตรวจ; ประกาศผลแล้วล็อกข้อมูลและแสดงหน้าสาธารณะ; Gold/Silver/Bronze หรือ BBB 1st/2nd/3rd สร้างสิทธิ์ Final และเปิดรอบอัตโนมัติ; เลข Final นำเข้า จับคู่ และบันทึกได้หลังตรวจรายการค้างครบ
8. **เสร็จในโค้ด — อัปโหลดรูปเกียรติบัตรผ่าน Drive** — หลังอนุมัติ ผู้สมัครเจ้าของอีเมลที่ยืนยันด้วย Google หรือผู้ประสานงานโรงเรียนเพิ่ม/แทน/ลบรูปได้ถึงวันปิดแก้ไข แยกโฟลเดอร์ตามรายการ/รอบ ตั้งชื่อ `เลขประจำตัว_ชื่อ_นามสกุล` และตรวจสิทธิ์/เวลาจาก server
9. **เสร็จในโค้ด — ความพร้อมระบบและคู่มือปฏิบัติการ** — เพิ่ม readiness check ที่ต้องพบ migration ล่าสุด, การตั้งค่า deploy/secret, การ backup/restore, การตรวจคิวและโควตา Google, และรายการตรวจรับก่อนเปิดใช้ใน [production runbook](production-runbook.md)

**เรื่อง service บน Railway:** ห้ามนำ worker ของ OCEC-Cert มาใช้ร่วมกัน หากยังติดข้อจำกัดจำนวน service ให้รันคิว PostgreSQL ของ Portal ด้วย worker loop ภายใน Portal API service ก่อน แล้วค่อยแยก Portal Worker ออกเมื่อโควตาและปริมาณงานรองรับ

**การตรวจชำระเงิน:** ไม่มี OCR หรือช่องกรอกยืนยันในหน้าตรวจ แอดมินดูสลิปและอนุมัติได้เมื่อมีไฟล์สลิป โดยยังบันทึกผู้อนุมัติและเวลาอนุมัติ

**งานโค้ดลำดับ 1–9 ครบแล้ว** ส่วนที่ต้องทำใน environment จริงคือเชื่อม Google OAuth, เปิด APIs และ scopes, เชื่อมบัญชีเจ้าของ Drive/ผู้ส่ง Gmail, เตรียม catalog/บัญชีรับเงินจริง, ตรวจคิว Gmail/Sheets, ทำ backup และ restore drill แล้ว deploy ตาม [production runbook](production-runbook.md)

**ขอบเขตตรวจสอบ:** ตรวจ build, syntax ของ server และ migration local ในรอบนี้; ยังไม่ได้ส่งอีเมลจริง, อัปโหลด/อ่าน Drive จริง, ซิงก์ Sheets จริง, restore production backup หรือ deploy Railway เพราะต้องใช้บัญชีและ environment ของผู้ให้บริการ

## สิ่งที่ยังเป็นค่าตั้งค่าตอนเชื่อมบริการ ไม่ใช่กติกาธุรกิจ

- Google OAuth client/authorized domains
- บัญชี Google Workspace ที่อนุญาตให้ Gmail API ส่งอีเมล
- Google Drive folder IDs และสิทธิ์ service account
- Google Spreadsheet ID, worksheet/tab และ mapping คอลัมน์
- รายชื่ออีเมลแอดมินเริ่มต้น
- ค่า environment variables ของ Railway

## ขอบเขตที่ไม่รวม

- ไม่ใช้ worker หรือฐานข้อมูลของ OCEC-Cert
- ไม่ทำ payment gateway
- ไม่ให้ Google Sheets เขียนกลับเข้า Portal
- ไม่ลบ application/payment history อัตโนมัติ
- ไม่เปลี่ยนระบบค้นหา/ออกเกียรติบัตรของ OCEC-Cert ในงาน backend นี้
